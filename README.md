# Split tunneling

**Универсальный список доменов для раздельного туннелирования в разных VPN-клиентах** и готовая конфигурация для Shadowrocket.

## Зачем нужен этот проект

Проект вырос из повседневного использования собственного VPN. При включённом VPN часть российских сайтов и приложений может перестать работать: сервис не принимает подключения с иностранных IP-адресов или определяет соединение как VPN. Это может проявляться сообщением «отключите VPN», отказом во входе, недоступностью видео или отдельных функций приложения.

Постоянно выключать VPN ради одного приложения и включать его обратно неудобно. Раздельное туннелирование позволяет назначить разные маршруты: обращения к выбранным сервисам идут напрямую через текущую сеть пользователя, а остальной трафик продолжает использовать VPN согласно настройкам клиента.

Этот список предназначен для настройки таких исключений. Основной сценарий — использование VPN из России, когда российскому сервису нужен прямой выход через местного провайдера. Прямое подключение использует IP текущей сети: за пределами России оно само по себе не даст российский адрес.

## Что представляет собой список

[main/domains/main.txt](main/domains/main.txt) — текстовый список доменов сервисов и связанных с ними ресурсов, для которых автор настраивает обход VPN. Его можно импортировать в совместимый клиент или преобразовать в нужный формат правил. Проект не привязан к одному приложению; для Shadowrocket дополнительно поддерживается готовая конфигурация.

Приложение обычно обращается не только к своему основному сайту. Вход в аккаунт, API, изображения, видео и другие функции могут использовать отдельные домены. Поэтому исключения только для адреса главной страницы бывает недостаточно: сайт открывается, а часть приложения по-прежнему обращается через VPN и сталкивается с ограничениями.

В подборке есть домены Госуслуг, российских банков, Ozon, Wildberries, Яндекса, 2GIS, видеосервисов и других приложений. Есть и отдельные иностранные сервисы с региональными подписками, например UFC Fight Pass. Для них маршрут должен соответствовать стране доступа, необходимой пользователю.

Сам по себе список не меняет маршрутизацию: в VPN-клиенте нужно назначить этим доменам прямое подключение. Это также не перечень сервисов, которые всегда блокируют любой VPN: поведение может зависеть от адреса выхода, сети и версии приложения.

## Как пополняется список

Автор ведёт подборку по мере личного использования сервисов и обнаружения новых проблем. Если приложение перестаёт работать с привычными правилами, автор изучает его сетевые обращения, находит недостающие домены и проверяет изменения на практике. По результатам список и конфигурация дополняются.

Такой подход помогает учитывать изменения, которые становятся заметны при обычном использовании: новый API, другой хост изображений или обновлённая инфраструктура видеосервиса. При этом сам факт обращения к домену ещё не означает, что его обязательно нужно направлять в обход VPN.

Обновления выходят по мере обнаружения и разбора проблем, без фиксированного расписания. Подборка отражает опыт автора и не претендует на полный охват всех российских сервисов или всех зависимостей каждого приложения. Сообщения о проблемах и проверенные дополнения от других пользователей приветствуются.

## Список доменов для разных клиентов

Скачайте [main.txt](https://raw.githubusercontent.com/theRomansky/split-tunneling-rules/main/main/domains/main.txt). В файле один домен на строку; пустые строки разделяют группы сервисов:

```text
example.com
api.example.com
```

Если ваш VPN-клиент умеет импортировать текстовый список исключений, загрузите файл и назначьте этим доменам прямое подключение. Если он требует другой синтаксис, используйте список для подготовки правил в его формате. Возможность работы с доменными правилами не означает автоматическую поддержку импорта `.txt`.

В самом списке нет политики маршрутизации: прямой выход задаётся в клиенте. Проверьте, включает ли запись `example.com` его поддомены или действует только на точное имя. Настройки Shadowrocket и его синтаксис не следует переносить в другие клиенты без преобразования.

Для обновления скачайте свежий список и повторите импорт или преобразование. Если клиент поддерживает обновление по URL, используйте прямую ссылку выше.

## Как устроена маршрутизация

В конфигурации Shadowrocket:

- `DIRECT` направляет соединение напрямую, с IP текущей сети пользователя.
- `PROXY` направляет соединение через выбранный в клиенте прокси-сервер.
- `DOMAIN` задаёт конкретный хост, `DOMAIN-SUFFIX` — домен и его поддомены.
- Правила идут по порядку; завершающий `FINAL,PROXY` применяется к трафику, который не совпал с предыдущими правилами. Системные и локальные исключения также заданы в конфигурации.

`DIRECT` не обеспечивает российский IP: за границей сервис увидит IP местной сети. Для региональной подписки страна выхода должна соответствовать требованиям сервиса. Готовая конфигурация не выбирает отдельный VPN-сервер для каждой страны.

Адресов VPN-серверов, паролей и подписок на серверы в текущих файлах нет. Собственное VPN-подключение необходимо настроить отдельно.

## Подключение в Shadowrocket

[Пошаговая инструкция со скриншотами](main/shadowrocket/README.md): сохранение `default.conf` в «Файлы», импорт через **Config → Import…**, проверка активной конфигурации и режима **Global Routing: Config**.

## Если сервис перестал работать

1. Убедитесь, что активен обновлённый файл и выбран режим маршрутизации по конфигурации.
2. Сравните работу приложения с VPN и с полностью выключенным VPN на той же сети.
3. Посмотрите обращения приложения и сработавшие правила в журнале соединений. Отчёт о доменах показывает факт обращения, но не доказывает, что запрос прошёл напрямую или что домен участвует в проверке региона.
4. Проверьте API, авторизацию и хосты контента: основной домен сервиса может идти напрямую, а новый API — через VPN.

Пример: 24 октября 2026 года пользователь подтвердил устранение сообщения о VPN в UFC Fight Pass после добавления точных DIRECT-правил для `mobile.api.onvesper.com`, `content-images.onvesper.com` и `vod-images.onvesper.com`. Это результат проверки на одном устройстве, а не гарантия для всех регионов и версий приложения.

## Обновление списков

Предложения можно отправлять через [Issues](https://github.com/theRomansky/split-tunneling-rules/issues) или Pull Request. Укажите сервис, клиент, симптом, домены и результат проверки с VPN и без него. В журналах и скриншотах скройте токены, данные аккаунта и ссылки на личные VPN-подписки.

При добавлении исключения обновляйте список `main/domains/main.txt` и конфигурацию `main/shadowrocket/default.conf` с учётом их формата. Для общих облаков и CDN предпочтительны конкретные хосты: исключение целого облачного домена может затронуть другие приложения. Не все домены аналитики и сторонних SDK нуждаются в прямом маршруте.

Минимальные проверки перед отправкой:

```sh
git diff --check
```

## Текущие ограничения

- Домены и требования сервисов меняются; работоспособность каждого правила не проверяется автоматически.
- Списки доменов и DIRECT-правила Shadowrocket исторически различаются и не являются автоматически сгенерированными копиями. Например, `amazonaws.com` есть в текстовых списках, а в Shadowrocket для него задан `PROXY` с отдельным исключением для `checkip.amazonaws.com`.
- В Shadowrocket сохранились пересекающиеся правила, включая DIRECT и PROXY для `ipleak.net`. Публичный IP-чекер может сам быть исключением и не отражать маршрут других приложений.
- В старых правилах есть шаблон `tile*.maps.2gis.com` типа `DOMAIN-SUFFIX`; его корректность не проверена.

## Лицензия и происхождение

Лицензия пока не выбрана. В конфигурации есть базовые и накопленные правила, происхождение которых полностью не задокументировано; условия их распространения требуют уточнения. Публичная доступность репозитория сама по себе не означает наличие открытой лицензии.
