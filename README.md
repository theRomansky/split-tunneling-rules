# Split tunneling

Правила раздельного туннелирования для **Shadowrocket** и текстовые списки доменов для других VPN-клиентов.

Проект помогает направлять обращения к выбранным сервисам напрямую через интернет-подключение пользователя, сохраняя VPN для остального трафика. Это полезно для сервисов, ограничивающих доступ с иностранных IP, и подписок с региональными ограничениями.

Списки пополняются по мере использования приложений и анализа их сетевых обращений. Среди сервисов — Госуслуги, российские банки, Ozon, Wildberries, Яндекс, 2GIS, видеосервисы и UFC Fight Pass. Это личная подборка, а не полный каталог всех необходимых исключений.

## Как устроена маршрутизация

В конфигурации Shadowrocket:

- `DIRECT` направляет соединение напрямую, с IP текущей сети пользователя.
- `PROXY` направляет соединение через выбранный в клиенте прокси-сервер.
- `DOMAIN` задаёт конкретный хост, `DOMAIN-SUFFIX` — домен и его поддомены.
- Правила идут по порядку; завершающий `FINAL,PROXY` применяется к трафику, который не совпал с предыдущими правилами. Системные и локальные исключения также заданы в конфигурации.

`DIRECT` не обеспечивает российский IP: за границей сервис увидит IP местной сети. Для региональной подписки страна выхода должна соответствовать требованиям сервиса. Готовая конфигурация не выбирает отдельный VPN-сервер для каждой страны.

Адресов VPN-серверов, паролей и подписок на серверы в текущих файлах нет. Собственное VPN-подключение необходимо настроить отдельно.

## Подключение в Shadowrocket

1. Сохраните копию своей конфигурации: файл проекта содержит не только доменные правила, но и общие настройки.
2. Скачайте файл по прямой ссылке из таблицы и импортируйте его как конфигурацию Shadowrocket. Если ваша версия поддерживает загрузку конфигурации по URL, используйте ту же прямую ссылку.
3. Выберите импортированную конфигурацию как активную и режим маршрутизации по конфигурации (`Config` / «Конфигурация»). Выбор VPN-сервера выполняется отдельно.
4. Переподключите VPN и полностью перезапустите проверяемое приложение.
5. Проверьте в журнале соединений клиента, что нужные хосты обрабатываются правилом `DIRECT`.

После обновлений в репозитории обновите загруженную конфигурацию в клиенте или скачайте и импортируйте файл повторно. Само изменение файла на GitHub не обновляет локальную копию на устройстве. Личные правки сохраняйте отдельно: повторный импорт может их заменить.

## Использование списка доменов

Выберите `.txt` или `.conf` в зависимости от требований клиента — содержимое одинаковое:

```text
example.com
api.example.com
```

Импортируйте файл в функцию исключений из VPN или используйте его для подготовки правил в формате своего клиента. Расширение `.conf` не делает этот список полной конфигурацией TrustTunnel или другого приложения.

В списках нет политики маршрутизации: прямой выход нужно задать в клиенте. Отдельно проверьте, включает ли запись `example.com` поддомены. Поддержка текстового импорта не означает поддержку правил Shadowrocket, wildcard или одинаковое поведение всех клиентов.

## Если сервис перестал работать

1. Убедитесь, что активен обновлённый файл и выбран режим маршрутизации по конфигурации.
2. Сравните работу приложения с VPN и с полностью выключенным VPN на той же сети.
3. Посмотрите обращения приложения и сработавшие правила в журнале соединений. Отчёт о доменах показывает факт обращения, но не доказывает, что запрос прошёл напрямую или что домен участвует в проверке региона.
4. Проверьте API, авторизацию и хосты контента: основной домен сервиса может идти напрямую, а новый API — через VPN.

Пример: 24 октября 2026 года пользователь подтвердил устранение сообщения о VPN в UFC Fight Pass после добавления точных DIRECT-правил для `mobile.api.onvesper.com`, `content-images.onvesper.com` и `vod-images.onvesper.com`. Это результат проверки на одном устройстве, а не гарантия для всех регионов и версий приложения.

## Обновление списков

Предложения можно отправлять через [Issues](https://github.com/theRomansky/split-tunneling-rules/issues) или Pull Request. Укажите сервис, клиент, симптом, домены и результат проверки с VPN и без него. В журналах и скриншотах скройте токены, данные аккаунта и ссылки на личные VPN-подписки.

При добавлении исключения обновляйте все три файла с учётом их формата. Для общих облаков и CDN предпочтительны конкретные хосты: исключение целого облачного домена может затронуть другие приложения. Не все домены аналитики и сторонних SDK нуждаются в прямом маршруте.

Минимальные проверки перед отправкой:

```sh
cmp main/domains/main.conf main/domains/main.txt
git diff --check
```

Инструкции по сопровождению находятся в [AGENTS.md](AGENTS.md).

## Текущие ограничения

- Домены и требования сервисов меняются; работоспособность каждого правила не проверяется автоматически.
- Списки доменов и DIRECT-правила Shadowrocket исторически различаются и не являются автоматически сгенерированными копиями. Например, `amazonaws.com` есть в текстовых списках, а в Shadowrocket для него задан `PROXY` с отдельным исключением для `checkip.amazonaws.com`.
- В Shadowrocket сохранились пересекающиеся правила, включая DIRECT и PROXY для `ipleak.net`. Публичный IP-чекер может сам быть исключением и не отражать маршрут других приложений.
- В старых правилах есть шаблон `tile*.maps.2gis.com` типа `DOMAIN-SUFFIX`; его корректность не проверена. Накопленные особенности перечислены в `AGENTS.md`.

## Лицензия и происхождение

Лицензия пока не выбрана. В конфигурации есть базовые и накопленные правила, происхождение которых полностью не задокументировано; условия их распространения требуют уточнения. Публичная доступность репозитория сама по себе не означает наличие открытой лицензии.
